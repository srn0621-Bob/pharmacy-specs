## 1. 简介

### 1.1 功能概述

对药品商城的缓存策略进行全面优化，提升系统性能和用户体验。

### 1.2 业务价值

- 显著提升系统响应速度
- 降低数据库查询压力
- 提升系统并发能力
- 改善用户体验

### 1.3 术语表

| 术语 | 定义 |
|------|------|
| 缓存命中率 | 从缓存中成功获取数据的请求占总请求的比例 |
| 缓存穿透 | 查询不存在的数据，导致每次都查询数据库 |
| 缓存击穿 | 热点数据过期，大量请求同时查询数据库 |
| 缓存雪崩 | 大量缓存同时过期，导致数据库压力骤增 |
| 缓存预热 | 系统启动时提前加载热点数据到缓存 |

## 2. 功能需求

### 2.1 核心功能（EARS格式）

#### FR-1: 药品分类缓存

**WHEN** 系统查询药品分类列表  
**THEN** 系统应将分类数据缓存1小时  
**AND** 分类数据更新时应清除缓存

#### FR-2: 热门药品缓存

**WHEN** 系统查询热门药品  
**THEN** 系统应将热门药品列表缓存30分钟  
**AND** 药品销量更新时应更新缓存

#### FR-3: 药品详情缓存

**WHEN** 系统查询药品详情  
**THEN** 系统应将药品详情缓存10分钟  
**AND** 药品信息更新时应清除缓存

#### FR-4: 购物车缓存

**WHEN** 用户操作购物车  
**THEN** 系统应将购物车数据缓存到Redis  
**AND** 缓存过期时间为7天

#### FR-5: 搜索结果缓存

**WHEN** 用户搜索药品  
**THEN** 系统应将搜索结果缓存5分钟  
**AND** 缓存Key应包含搜索关键词和分页参数

#### FR-6: 缓存预热

**WHEN** 系统启动  
**THEN** 系统应自动加载以下数据到缓存：
- 药品分类列表
- 热门药品Top 100
- 快捷分类列表

#### FR-7: 缓存更新策略

**WHEN** 管理员更新药品信息  
**THEN** 系统应自动清除相关缓存：
- 药品详情缓存
- 分类药品列表缓存
- 搜索结果缓存

## 3. 非功能性需求

### 3.1 性能要求

| 指标 | 要求 |
|------|------|
| 缓存命中率 | > 90% |
| 缓存响应时间 | < 50ms |
| 缓存预热时间 | < 30秒 |
| 缓存更新延迟 | < 1秒 |

### 3.2 可用性要求

- Redis不可用时系统应降级到直接查询数据库
- 缓存失败不应影响主流程
- 缓存更新失败应记录日志并告警

### 3.3 可维护性要求

- 缓存Key应有统一的命名规范
- 缓存过期时间应可配置
- 缓存策略应易于调整

---

## 4. 约束条件

### 4.1 技术约束

- 必须使用Redis作为缓存存储
- 缓存数据必须序列化为JSON格式
- 缓存Key必须遵循命名规范

### 4.2 业务约束

- 缓存数据必须与数据库数据保持一致
- 敏感数据不应缓存
- 缓存过期时间应合理设置

### 4.3 数据约束

- 单个缓存值大小不超过1MB
- 缓存Key长度不超过256字符
- 缓存总量不超过Redis内存限制

## 5. 缓存策略设计

### 5.1 缓存Key命名规范

```
格式: {模块}:{功能}:{参数}

示例:
- 药品分类列表: mall:category:list
- 药品详情: mall:drug:detail:{drugId}
- 搜索结果: mall:search:{keyword}:{page}:{size}
- 购物车: mall:cart:{userId}
- 热门药品: mall:drug:hot:{limit}
```

### 5.2 缓存过期时间策略

| 数据类型 | 过期时间 | 理由 |
|---------|---------|------|
| 药品分类 | 1小时 | 分类数据变化频率低 |
| 药品详情 | 10分钟 | 价格库存可能变化 |
| 热门药品 | 30分钟 | 销量数据定期更新 |
| 搜索结果 | 5分钟 | 搜索结果实时性要求高 |
| 购物车 | 7天 | 用户可能长时间不操作 |
| 推荐列表 | 30分钟 | 推荐数据定期更新 |

### 5.3 缓存更新策略

| 场景 | 更新策略 |
|------|---------|
| 药品信息更新 | 删除药品详情缓存、分类列表缓存、搜索缓存 |
| 分类信息更新 | 删除分类列表缓存、分类药品缓存 |
| 库存变化 | 删除药品详情缓存 |
| 价格变化 | 删除药品详情缓存、搜索缓存 |
| 购物车操作 | 更新购物车缓存 |

## 6. 防止缓存问题的方案

### 6.1 防止缓存穿透

**问题:** 查询不存在的数据，导致每次都查询数据库

**解决方案:**
- 对不存在的数据也缓存（缓存空值）
- 缓存空值的过期时间设置为5分钟
- 使用布隆过滤器过滤不存在的请求

### 6.2 防止缓存击穿

**问题:** 热点数据过期，大量请求同时查询数据库

**解决方案:**
- 使用分布式锁（Redis SETNX）
- 只允许一个请求查询数据库
- 其他请求等待或返回旧数据

### 6.3 防止缓存雪崩

**问题:** 大量缓存同时过期，导致数据库压力骤增

**解决方案:**
- 缓存过期时间添加随机值（±10%）
- 热点数据设置永不过期
- 使用多级缓存（本地缓存 + Redis）

## 8. 测试场景

### 8.1 正常场景

| 场景 | 前置条件 | 操作 | 预期结果 |
|------|---------|------|---------|
| 查询药品分类 | 缓存为空 | 第一次查询 | 从数据库查询并缓存 |
| 查询药品分类 | 缓存存在 | 第二次查询 | 从缓存返回 |
| 更新药品信息 | 缓存存在 | 更新药品 | 缓存被清除 |
| 系统启动 | 缓存为空 | 启动系统 | 自动预热缓存 |

### 8.2 异常场景

| 场景 | 前置条件 | 操作 | 预期结果 |
|------|---------|------|---------|
| Redis不可用 | Redis宕机 | 查询数据 | 降级到数据库查询 |
| 缓存过期 | 缓存刚好过期 | 大量并发请求 | 只有一个请求查询数据库 |
| 缓存更新失败 | Redis异常 | 更新数据 | 记录日志，不影响主流程 |

## 10. 风险与限制

### 10.1 风险

- 缓存数据可能与数据库不一致
- Redis内存可能不足
- 缓存更新策略可能不完善

### 10.2 限制

- 依赖Redis服务的稳定性
- 缓存数据有延迟
- 不适合缓存实时性要求极高的数据

### 10.3 未来优化方向

- 引入多级缓存（本地缓存 + Redis）
- 使用缓存预加载提升命中率
- 实现智能缓存淘汰策略
- 引入缓存监控和告警
