## 1. 简介

### 1.1 功能概述

为药品商城订单提供物流信息查询功能，用户可以查看订单的物流轨迹和配送状态。

### 1.2 业务价值

- 提升用户体验，让用户实时了解订单配送进度
- 减少客服咨询压力
- 增强用户对平台的信任度

### 1.3 术语表

| 术语 | 定义 |
|------|------|
| 物流轨迹 | 快递包裹从发货到签收的全部流转记录 |
| 快递公司编码 | 快递100系统中的快递公司标识符 |
| 快递单号 | 快递公司分配的唯一追踪号码 |
| 快递100 | 第三方物流信息聚合查询服务 |
| 物流状态 | 订单当前的配送状态（待发货、运输中、派送中、已签收等） |

## 2. 功能需求

### 2.1 核心功能（EARS格式）

#### FR-1: 查询订单物流信息

**WHEN** 用户在订单详情页点击"查看物流"  
**IF** 订单状态为"待收货"或"已完成"  
**THEN** 系统应显示该订单的物流轨迹信息  
**AND** 物流轨迹按时间倒序排列（最新的在最上面）

#### FR-2: 物流信息展示

**WHEN** 系统成功获取物流信息  
**THEN** 系统应展示以下信息：
- 快递公司名称
- 快递单号
- 物流状态（运输中/派送中/已签收等）
- 物流轨迹列表（时间、地点、状态描述）

#### FR-3: 无物流信息处理

**WHEN** 订单尚未发货  
**THEN** 系统应提示"订单暂未发货，暂无物流信息"

**WHEN** 订单已发货但快递100查询不到物流信息  
**THEN** 系统应提示"物流信息更新中，请稍后再试"

#### FR-4: 物流信息缓存

**WHEN** 系统查询到物流信息  
**THEN** 系统应将物流信息缓存5分钟  
**AND** 5分钟内的重复查询直接返回缓存数据

#### FR-5: 物流状态识别

**WHEN** 系统获取物流轨迹  
**THEN** 系统应根据物流轨迹内容识别当前物流状态：
- 包含"已签收"或"签收" → 已签收
- 包含"派送"或"派件" → 派送中
- 包含"到达"或"到件" → 运输中
- 其他 → 运输中

## 3. 非功能性需求

### 3.1 性能要求

| 指标 | 要求 |
|------|------|
| 响应时间 | 首次查询 < 3秒，缓存命中 < 500ms |
| 并发支持 | 支持100个用户同时查询物流 |
| 快递100 API超时 | 10秒超时，超时返回友好提示 |

### 3.2 可用性要求

- 快递100 API不可用时，系统应降级处理，提示用户稍后再试
- 物流查询失败不应影响订单详情页的其他功能

### 3.3 安全性要求

- 用户只能查询自己的订单物流信息
- 快递100 API调用需要签名验证
- 敏感信息（收件人手机号）需脱敏显示

---

## 4. 约束条件

### 4.1 技术约束

- 必须使用快递100 API进行物流查询
- 必须使用Redis缓存物流信息
- 必须复用现有的Kuaidi100Util工具类

### 4.2 业务约束

- 只有"待收货"和"已完成"状态的订单才能查询物流
- 物流信息查询不收取用户费用
- 快递100 API调用次数有限制，需合理使用缓存

### 4.3 数据约束

- 订单必须有快递单号才能查询物流
- 快递公司编码必须是快递100支持的编码
- 物流轨迹最多展示最近50条记录

## 6. 数据模型

### 6.1 订单物流信息DTO

```java
public class OrderLogisticsDTO {
    private Long orderId;              // 订单ID
    private String orderNo;            // 订单号
    private String expressCompany;     // 快递公司名称
    private String expressCode;        // 快递公司编码
    private String expressNo;          // 快递单号
    private String logisticsStatus;    // 物流状态
    private List<LogisticsTrace> logisticsTraces;  // 物流轨迹
    private String receiverName;       // 收件人姓名（脱敏）
    private String receiverPhone;      // 收件人电话（脱敏）
    private String receiverAddress;    // 收件地址（脱敏）
    private String message;            // 提示信息
}
```

### 6.2 物流轨迹DTO

```java
public class LogisticsTrace {
    private Integer processNo;         // 流程序号
    private String processTime;        // 处理时间
    private String processRemark;      // 处理描述
}
```

## 7. 验收标准

### 7.1 功能验收

- [ ] 用户能查询"待收货"状态订单的物流信息
- [ ] 用户能查询"已完成"状态订单的物流信息
- [ ] 物流轨迹按时间倒序排列
- [ ] 未发货订单显示"暂无物流信息"提示
- [ ] 物流查询失败显示友好提示信息
- [ ] 用户只能查询自己的订单物流

### 7.2 性能验收

- [ ] 首次查询响应时间 < 3秒
- [ ] 缓存命中响应时间 < 500ms
- [ ] 快递100 API超时时间设置为10秒
- [ ] 支持100个用户并发查询

### 7.3 安全验收

- [ ] 用户A无法查询用户B的订单物流
- [ ] 收件人手机号脱敏显示（138****5678）
- [ ] 收件人姓名脱敏显示（张**）
- [ ] 收件地址部分脱敏（隐藏门牌号）

### 7.4 异常处理验收

- [ ] 订单不存在时返回友好错误提示
- [ ] 订单状态不支持查询物流时返回提示
- [ ] 快递100 API调用失败时返回降级提示
- [ ] 快递100 API超时时返回友好提示

## 8. 测试场景

### 8.1 正常场景

| 场景 | 前置条件 | 操作 | 预期结果 |
|------|---------|------|---------|
| 查询待收货订单物流 | 订单状态为"待收货"，有快递单号 | 点击"查看物流" | 显示物流轨迹列表 |
| 查询已完成订单物流 | 订单状态为"已完成" | 点击"查看物流" | 显示完整物流轨迹（含签收记录） |
| 缓存命中 | 5分钟内重复查询同一订单 | 点击"查看物流" | 快速返回缓存数据 |

### 8.2 异常场景

| 场景 | 前置条件 | 操作 | 预期结果 |
|------|---------|------|---------|
| 查询未发货订单 | 订单状态为"待发货" | 点击"查看物流" | 提示"订单暂未发货" |
| 查询他人订单 | 用户A尝试查询用户B的订单 | 调用API | 返回"订单不存在或无权访问" |
| 快递100 API失败 | 快递100服务不可用 | 点击"查看物流" | 提示"物流信息更新中，请稍后再试" |
| 快递单号错误 | 订单有快递单号但查询不到 | 点击"查看物流" | 提示"物流信息更新中，请稍后再试" |

## 10. 风险与限制

### 10.1 风险

- 快递100 API调用次数有限制，超出限制会影响服务
- 快递100 API可能不稳定，需要做好降级处理
- 部分快递公司可能不支持实时查询

### 10.2 限制

- 物流信息更新有延迟（取决于快递公司和快递100）
- 只支持快递100已接入的快递公司
- 物流轨迹最多展示最近50条记录
