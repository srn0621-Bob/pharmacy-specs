# 处方审核触发逻辑调查报告

## 概述
本报告详细说明了医生端Android应用中处方审核的完整触发流程和相关逻辑。

## 处方审核流程

### 1. 处方创建阶段 (PrescribeActivity)

**文件位置**: `app/src/main/java/com/adinnet/demo/ui/prescription/PrescribeActivity.java`

**触发入口**:
- 医生在问诊/复诊订单中选择"开处方"
- 进入处方编辑界面，可以添加：
  - 疾病信息（通过 `DiseaseListActivity` 选择）
  - 药品信息（通过 `DrugListActivity` 选择）
  - 禁忌信息（肾功能、肝功能、妇女状态、过敏等）

**第一次提交 - 创建处方**:
```java
// 点击"提交"按钮触发
case R.id.btn_commit:
    // 验证疾病和药品信息
    if (DataUtils.isEmpty(diseaseData)) {
        RxToast.normal("请选择疾病");
        return;
    }
    if (DataUtils.isEmpty(drugsData)) {
        RxToast.normal("请选择药品");
        return;
    }
    
    // 调用API创建处方
    Api.getInstanceService().commitPrescribe(reqCreatePrescribe)
        .subscribe(new ResponseBoxSubscriber<Object>() {
            @Override
            public void onSuccess(Object results) {
                // 跳转到处方详情页面
                PrescribeDetailActivity.start("", orderId, type);
                finish();
            }
        });
```

**API接口**: `POST /pre/create`
- 提交处方基本信息（疾病、药品、禁忌等）
- 此时处方状态为 `NOTSIGN`（未签名）

### 2. 处方签名阶段 (PrescribeDetailActivity)

**文件位置**: `app/src/main/java/com/adinnet/demo/ui/prescription/PrescribeDetailActivity.java`

**医生签名认证**:

case R.id.tv_auth_status:   // 医生签名

- 医生进行电子签名认证
- 签名成功后，处方状态从 `NOTSIGN` 变为 `SIGN`（已签名）

---

### 3. 提交审核阶段 (关键触发点)

**触发条件判断**:
```java
// PrescribeDetailEntity.java 中的判断逻辑
public boolean isNotSign() {
    return "NOTSIGN".equals(checkStatus);
}

public boolean isCanCommit() {
    return "SIGN".equals(checkStatus);  // 只有已签名状态才能提交审核
}
```

**提交审核触发**:
```java
case R.id.btn_commit:   // 提交审方按钮
    if (prescribeDetailEntity.isCanCommit()) {
        // 第二次提交 - 提交处方审核
        Api.getInstanceService().commitPrescribeResult(ReqId2.create(prescribeDetailEntity.id, "", ""))
            .subscribe(new ResponseBoxSubscriber<Object>() {
                @Override
                public void onSuccess(Object results) {
                    // 跳转到审核结果页面
                    Intent intent = new Intent(App.getAppContext(), PrescribeResultActivity.class)
                        .putExtra(Constants.ID, prescribeDetailEntity.id)
                        .putExtra(Constants.ENTITY, "")
                        .putExtra(Constants.TYPE, "");
                    AppManager.get().startActivity(intent);
                    finish();
                }
            });
    }
```

**API接口**: `POST /pre/commit`
- 这是**真正触发处方审核的关键接口**
- 提交后处方状态变为 `WAIT`（待审核）

---

### 4. 审核结果查看 (PrescribeResultActivity)

**文件位置**: `app/src/main/java/com/adinnet/demo/ui/prescription/PrescribeResultActivity.java`

**处方状态说明**:
```java
// PrescribeSignEntity.java
public String status;  // WAIT-提交成功 PASS-审核通过 REJECT-审核驳回

public boolean isPass() {
    return "PASS".equals(status);
}

public boolean isWait() {
    return "WAIT".equals(status);
}

public boolean isReject() {
    return "REJECT".equals(status);
}
```

**审核结果展示**:
- `WAIT`: 处方正在审核中
- `PASS`: 处方审核通过，已发给患者
- `REJECT`: 处方审核失败，需要重新提交

## 处方状态流转图

```
NOTSIGN (未签名)
    ↓
  [医生签名] POST /pre/sign
    ↓
SIGN (已签名)
    ↓
  [提交审核] POST /pre/commit  ← 关键触发点
    ↓
WAIT (待审核)
    ↓
  [药师审核]
    ↓
PASS (审核通过) / REJECT (审核驳回)
```

---

## 关键API接口总结

| 接口路径 | 方法 | 说明 | 状态变化 |
|---------|------|------|---------|
| `/pre/create` | POST | 创建处方 | → NOTSIGN |
| `/pre/sign` | POST | 医生签名 | NOTSIGN → SIGN |
| `/pre/commit` | POST | **提交审核** | SIGN → WAIT |
| `/pre/status` | POST | 查询处方状态 | - |
| `/pre/details` | POST | 查询处方详情 | - |

## 核心触发逻辑总结

**处方审核的触发需要满足以下条件**:

1. ✅ 处方已创建（调用 `/pre/create`）
2. ✅ 医生已完成电子签名（调用 `/pre/sign`，状态为 `SIGN`）
3. ✅ 点击"提交审方"按钮
4. ✅ 调用 `/pre/commit` 接口

**关键代码位置**:
- **触发入口**: `PrescribeDetailActivity.java` 第 130-145 行
- **状态判断**: `PrescribeDetailEntity.java` 第 56-60 行
- **API定义**: `ApiService.java` 第 330-334 行

## 结论

**处方审核的核心触发点**是在 `PrescribeDetailActivity` 中点击"提交审方"按钮后，调用 `POST /pre/commit` 接口。此操作必须在医生完成电子签名（状态为 `SIGN`）后才能执行。提交后，处方进入 `WAIT` 状态，等待药师审核。
